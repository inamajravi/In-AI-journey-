Build-vs-buy tradeoffs for enterprise AI tooling

Level 5 · Topic 2 of 5

Why it matters

Many architect decisions are about what not to build. A clear framework makes your recommendations credible.

Core concepts

  • Criteria: strategic differentiation, time to value, integration effort, security and compliance fit, total cost of ownership, vendor lock-in and exit cost.
  • Buy for commodity: generic chat, summarisation, standard observability. Build for differentiation: domain logic like screening rules, proprietary data workflows.
  • Hybrid is common: buy infrastructure, build the domain layer on top behind clean interfaces.
  • Hidden costs: evaluation, maintenance, on-call, security review and keeping up with model changes.
  • Exit plan: decide up front how you would leave a vendor, and test it lightly.

Hands-on exercise

Pick one capability (e.g. LLM observability). Score build vs two vendor options against the criteria above, estimate 12-month cost for each, and write a one-page recommendation including the risks.

Self-check

  1. What is truly differentiating in your domain?
  2. What is the exit cost of each option?
  3. Which hidden costs did you include for 'build'?
