Tokens, context windows, sampling, system prompts

Level 1 · Topic 1 of 4

Why it matters

Every cost, latency and quality decision in an AI application traces back to these four ideas. An architect who can't reason about them is guessing.

Core concepts

  • Tokens are the units a model reads and writes (word fragments, not words). You pay per input and output token, and limits are counted in tokens. Code and non-English text usually cost more tokens per character.
  • Context window is the total tokens (prompt + history + output) the model can attend to in one call. The model has no memory between calls — you resend whatever it needs every time.
  • Temperature / top-p control randomness. Low temperature (0–0.3) for extraction, classification, screening decisions; higher for brainstorming. Don't tune both at once.
  • System prompt sets role, rules, output format and constraints for the whole conversation. It is your main lever for consistent behaviour and the first place to put guardrails.
  • Long context is not free: more tokens means higher cost and latency, and models can miss details buried in the middle. Send what is relevant, not everything.
  • max_tokens caps output length; if the answer is cut off, stop_reason will tell you.

Hands-on exercise

Take the sanctions-screening 'explain' use case. Write one system prompt that fixes role, tone, and output format. Run the same user question 5 times at temperature 0 and 5 times at temperature 1. Record how much the outputs vary and note which setting you'd use in production and why.

Self-check

  1. Why does a long conversation get more expensive with every turn?
  2. When would you set temperature to 0, and when is that still not fully deterministic?
  3. What belongs in a system prompt versus in the user message?
  4. What happens when your prompt plus expected output exceeds the context window?
