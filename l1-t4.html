Build one raw API call with tool use

Level 1 · Topic 4 of 4

Why it matters

Doing it once with plain HTTP, no SDK or framework, is the fastest way to truly own the mechanics. Everything later builds on this.

Core concepts

  • Endpoint and headers: POST to /v1/messages with x-api-key, anthropic-version and content-type headers. Keep the key in an environment variable, never in code or chat.
  • Round trip: send the question and tools, read stop_reason, execute the matching function, then send the tool_result back so the model can write the final answer.
  • Model name: use a current model string from the docs; names change over time, so keep it in config, not hard-coded across files.
  • Keep it small: one tool, one happy path, one error path. Resist adding abstractions yet.

Starter code

import os, requests

URL = "https://api.anthropic.com/v1/messages"
HEADERS = {
    "x-api-key": os.environ["ANTHROPIC_API_KEY"],
    "anthropic-version": "2023-06-01",
    "content-type": "application/json",
}
tools = [{
    "name": "screen_name",
    "description": "Screen a name against a sanctions list and return match candidates.",
    "input_schema": {
        "type": "object",
        "properties": {
            "name": {"type": "string"},
            "list": {"type": "string", "enum": ["OFAC_SDN", "UN"]},
        },
        "required": ["name"],
    },
}]
body = {
    "model": "claude-sonnet-5-5",
    "max_tokens": 1024,
    "tools": tools,
    "messages": [{"role": "user", "content": "Is 'Ivan Petrov' on the OFAC SDN list?"}],
}
r = requests.post(URL, headers=HEADERS, json=body).json()
print(r["stop_reason"])  # 'tool_use' when the model wants your function
# Next: find the tool_use block, run your function, append a tool_result
# message, and call the API again for the final answer.

Hands-on exercise

Implement the full round trip in your own stack (C# HttpClient or Python): first call, execute a stub screen_name function, send the tool_result, print the final answer. Then break it on purpose: return an error from your tool and see how the model responds.

Self-check

  1. Which part of the round trip is your code, and which is the model?
  2. What do you send back after running the tool?
  3. How would you add a second tool without restructuring everything?
  4. Where does the API key live in your setup, and how is it kept out of source control?
