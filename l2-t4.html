Add a RAG layer to a real endpoint (sanctions explain)

Level 2 · Topic 4 of 5

Why it matters

Applying RAG to your own production-style project turns theory into interview-ready evidence.

Core concepts

  • Scope: the 'explain' endpoint should justify a match using retrieved context (list entry details, matching rules, policy text) instead of static strings.
  • Grounding: instruct the model to answer only from the provided context and to cite which entries it used.
  • Matching stays deterministic: keep the scoring (fuzzy, phonetic, Levenshtein) in code. The LLM explains the decision; it does not make it.
  • Measure: record latency and tokens with and without retrieval, and compare answer quality on a fixed question set.

Hands-on exercise

Add retrieval to explain: fetch the matched list entries plus the relevant rule text, pass them as context, and require citations. Write 10 test cases and compare against the old static explanation on correctness and usefulness.

Self-check

  1. Which parts of screening must never be delegated to the LLM?
  2. How do you verify the explanation is grounded in the retrieved data?
  3. What did retrieval cost you in latency and tokens?
