Agentic loops: planner/executor, tool-calling chains

Level 2 · Topic 2 of 5

Why it matters

Agents are powerful and expensive. An architect's value is knowing when a simple workflow is enough and when a loop is justified.

Core concepts

  • The loop: model decides, calls a tool, sees the result, decides again, until it produces a final answer or hits a stop condition. It is the tool-use round trip repeated.
  • Workflow vs agent: a fixed sequence of steps (prompt chaining, routing, parallel calls) is cheaper, faster and more predictable than letting the model choose its own path. Use an agent only when the steps genuinely can't be known in advance.
  • Planner/executor: one call produces a plan, then separate calls execute steps. Easier to inspect and cap than a free-running loop.
  • Guardrails: max iterations, token and cost budgets, timeouts, an allow-list of tools, and human approval for irreversible actions.
  • Tool design: small, well-named tools with clear descriptions and strict schemas beat a few giant ones. Return concise, structured results so context doesn't bloat.
  • Observability: log every step (tool, input, output, tokens). Without this, agent failures are impossible to debug.

Hands-on exercise

Design (on paper) an agent that investigates a flagged payment: search the watchlist, fetch customer history, summarise. Then redesign it as a fixed 3-step workflow. Compare cost, latency, predictability and what would justify the agent version.

Self-check

  1. What stops an agent loop from running forever?
  2. Give one case where a fixed workflow beats an agent.
  3. Why are small, precise tools better than one big tool?
  4. Which actions should always require human approval?
